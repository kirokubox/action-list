# action-order（リポジトリ名は `action-list`）

仕事以外の直近数時間について「次やる順番」だけを組み立てるモバイルファーストWebアプリです。

一日全体の予定表やタスク管理アプリではありません。完了記録・回数・日付・締切・時刻・通知は持ちません。「完了」「済み」という語もUIに使いません。

- かぞえ帳 = 回数・最終日
- Googleカレンダー = 実績時間
- 本アプリ = 次やる順番

というSOT（正本）分担を前提にしています。

## 画面の構造（音楽アプリのプレイリストに近い）

スマホ画面を2列にしています。

- 左列「今回の流れ」（約65%）… 今回実行する行動の一列の順番。時間帯の区切りは置かない
- 右列「定番」（約35%）… 保存される定番の行動メニュー。コンパクトな行表示

操作：

- 右列の項目を1回タップ → 左列のどこへ入れるか（先頭 / 各項目の間 / 末尾）を選ぶシートが出る
- 同じ定番項目を左列へ何度でも追加できる（追加された項目はそれぞれ独立）
- 左列は長押しドラッグで並べ替え、横スワイプで「今回の流れから外す」（定番メニューには残る）
- 左列の「新しい流れ」で左列だけを空にする（確認あり・アンドゥあり。定番メニューは消えない）
- 右列の「編集」でタップ＝名称編集／長押しドラッグ＝メニュー内の並べ替え。「＋ 定番を追加」で新規追加

## データの保存場所

- localStorage（キー：`action-list-data`）にのみ保存します。サーバー・ログイン・自動同期はありません
- 保存形式は `{ version: 2, menu: [...], flow: [...] }`。`menu` が定番メニュー、`flow` が今回の流れ
- 左列（今回の流れ）は一時リストですが、再読み込み・アプリ再起動では消えません。日付変更による自動リセットもしません（就寝前に翌朝の流れを作れるようにするため）。空にするのは「新しい流れ」だけ
- v1（区切り1本の1列リスト）のデータは初回起動時に自動で定番メニューへ移行します。移行前の生データは `action-list-data-v1-backup` に1回だけ退避します

## バックアップ・インポート

- ヘッダー右「⋯」の「定番メニューを書き出す」で `action-order-menu-YYYY-MM-DD.json` を保存します（バックアップ対象は定番メニューのみ。左列は一時リストなので含めません）
- 「定番メニューを取り込む」は追加型インポートです。既存項目は消さず、id重複・同名は追加しません。v1バックアップ・旧シードJSON（`items` 形式）も読み込めます
- 「サンプルメニューを追加」で汎用サンプルを追加できます（同名はスキップ）
- 書き出したJSONは資料フォルダ（`05_開発・Webアプリ\13_action-list\backup_json`）などに保管してください。リポジトリ・`public` には置きません

## 正式名称・アイコンについて

アプリ名は `action-order` で確定しています（2026-08-01）。リポジトリ名・フォルダ名は `action-list` のままです。
配色とアイコンは仮のプレースホルダーで、正式なデザインは後日差し替えます。
